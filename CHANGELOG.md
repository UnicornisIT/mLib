## [0.0.5-alpha] - 2026-10-23

### Added

- Раздел «Перенести фонотеку» в музыкальном профиле: экспорт Apple Music в CSV превращается в каталог треков с точными названиями, альбомами, ссылками на обложки и ссылками на Apple Music и Spotify. Дубли по ISRC и Apple id убираются, повторная загрузка только добавляет новые треки.
- Поиск треков каталога через iTunes lookup идёт в фоне пачками по 100 с паузами, по витринам ru → us → tr (`ITUNES_STOREFRONTS`, отключается через `ITUNES_LOOKUP_ENABLED=false`). Состояние хранится в базе, поэтому перенос продолжается после перезапуска, а для «не найдено» есть повтор. Аудио-превью и обложки Apple не скачиваются.
- Файл можно загрузить сразу в выбранный трек каталога, привязать вручную или отвязать. При импорте папки и обычной загрузке файл привязывается автоматически по ISRC из тегов (ID3, Vorbis, MP4), а затем по исполнителю, названию и длительности (±2 с); при неоднозначном совпадении предлагаются кандидаты.
- В плейлист можно добавить трек каталога без файла; по флагу перенос создаёт плейлисты из столбца «Playlist name».
- Перенос фонотеки через TuneMyMusic из любого сервиса: Spotify, Apple Music, YouTube Music, Deezer, TIDAL, Amazon Music, SoundCloud, Яндекс Музыки и других. Принимается CSV TuneMyMusic с колонкой «<Сервис> - id» (обязательны только «Track name» и «Artist name»; «Type» = Favorite попадает в плейлист «Любимые треки») и TXT со строками «Исполнитель - Название». Треки с Apple id ищутся в Apple Music пачками, остальные — поиском по исполнителю и названию со строгой проверкой (около 17 треков в минуту, в фоне). Повторный импорт узнаёт треки по Apple id, ISRC, id сервиса и исполнителю с названием. Миграция `0007` снимает NOT NULL с `apple_track_id` без пересоздания таблицы, поэтому привязки файлов и плейлистов сохраняются.
- Раздел «Каталог» в musicLib в духе Apple Music: сетка обложек треков и альбомов каталога, поиск и фильтры «С файлом», «Нет файла», «Не найдены в Apple». Карточки без файла приглушены и подписаны «Нет файла»; аудиофайл можно перетащить прямо на карточку или строку альбома. Вид «Список» показывает треки строками со статусом; счётчики на странице переноса («треков в каталоге», «найдено в Apple Music», «не найдено») открывают соответствующий список, а у ненайденных треков есть ссылки для поиска в Apple Music и Spotify.
- Альбомы из перенесённой фонотеки сразу появляются в разделе «Альбомы» вместе с альбомами из файлов: треки с одинаковым названием альбома собираются в один альбом, если у них общий исполнитель или один альбом Apple (разные издания и саундтреки не дробятся, одноимённые альбомы разных исполнителей не склеиваются), исполнитель альбома — тот, кто указан в большинстве треков, а альбом из тегов привязанного файла не дублируется. Альбомы без файлов подписаны «Нет файлов» и открываются страницей альбома каталога.
- Исполнители из перенесённой фонотеки появляются в разделе «Исполнители»: треки группируются по основному исполнителю (гости из «feat.» и «&» не получают отдельных карточек), у каждого есть страница с альбомами и треками каталога. Названия исполнителей в списках треков, плеере и на страницах трека и альбома ведут на исполнителя каталога. Локальный альбом или исполнитель из тегов скрывается, только если все его файлы привязаны к каталогу.
- Жанры из Apple Music для треков каталога: раздел «Жанры» показывает их вместе с жанрами файлов без привязки и открывает список треков каталога выбранного жанра. Для уже перенесённых треков жанры один раз подгружаются в фоне (миграция `0008` добавляет колонку без пересоздания таблицы). «Жанры» перенесены в верхнюю группу меню.
- Футер musicLib прижат к низу страницы на одной линии с блоком «Мой профиль»; длинное имя исполнителя в плеере обрезается многоточием и не наезжает на сердечко.
- Поиск в шапке работает по мере ввода, без Enter, и ищет по каталогу: исполнители, треки (сначала совпадения по названию) и альбомы, а файлы вне каталога показаны отдельно.
- Страница трека и альбома каталога с фоном-градиентом по цвету обложки, ссылками на Apple Music и поиск в Spotify, загрузкой файла кнопкой или перетаскиванием, привязкой файла из медиатеки и отвязкой. Встроенного воспроизведения через Apple или Spotify нет, обложки Apple только показываются по ссылке.
- В списках треков и плеере для привязанных файлов показываются название, исполнитель, альбом и обложка из каталога (теги файла не меняются, обложка из файла приоритетнее Apple). В меню трека появились «Открыть в каталоге» и «Связать с каталогом» с выбором из кандидатов. Файл, привязанный к каталогу, больше не попадает в «Требует внимания» из-за неполных тегов.

### Fixed

- Поиск, фильтр «Все треки» и фильтры жанров не учитывали регистр только для латиницы: SQLite сравнивает без учёта регистра лишь ASCII, поэтому «александр» не находил «Александр». Теперь в SQLite используется Unicode-сравнение через `str.casefold`.
- Вставка трека не в конец плейлиста больше не падает на проверке уникальности позиций.
- Счётчики переноса фонотеки («найдено», «не найдено», «ошибки») больше не отстают на пачку и верны при отключённом поиске в Apple Music.
- Анимация на главных экранах модулей: двигается только декор, а карточки статистики и кнопка рекомендуемой игры стоят на месте. Кадры плёнки, книги и предметы коллекций масштабируются по своей области и больше не обрезаются краем карточки; заголовок musicLib не обрезается на средней ширине, панель статистики movieLib не перекрывает кнопки.
- На телефоне кнопки «Добавить…» в шапках bookLib, gameLib, wishLib, collectLib и кнопки «Удалить» в редакторах снова показываются иконкой, а не обрезанным текстом.
- Проверка обновлений больше не показывает ошибку, пока новый выпуск публикуется (404 на `latest.yml`): Desktop сообщает «Новая версия ещё публикуется» и повторяет проверку через 30 минут вместо 6 часов.

### Changed

- Выпуск запускается вручную из `main` (`Run workflow` с `version` и `publish`) вместо отправки тега. Release сначала создаётся черновиком со всеми файлами и только затем публикуется; тег появляется в момент публикации, поэтому упавшая сборка не оставляет тега без Release.

## [0.0.4-alpha] - 2026-10-17

### Fixed

- Загрузка музыкальных треков и книг в Windows Desktop шла через неработающий в desktop-сборке прокси Next.js; теперь запросы идут напрямую в backend.
- Возобновляемая загрузка видео отбрасывает байты, оставшиеся от прерванного запроса, и больше не портит файл.
- Страховочная копия перед миграциями содержит только базы данных: запуск после обновления больше не копирует всю медиатеку и не упирается в таймаут.

### Changed

- Desktop показывает окно запуска; backend получает до 10 минут на миграции вместо 60 секунд.
- Restore копии без медиа не трогает текущую медиатеку.
- Релизный workflow: проверка всех источников версии и release notes, полный CI перед сборкой, отдельный job публикации с `contents: write`, запрет перевыпуска существующего Release, Actions закреплены по SHA, `persist-credentials: false`.
- Порядок выпуска описан в `docs/RELEASING.md`.

## Начальная разработка - 2026-08-14

Изначально планировалась как `0.1.0`; под этим номером не выпускалась.

### Added

- Единая self-hosted оболочка для музыки, фильмов и сериалов, книг, коллекций, игр и желаний.
- Первоначальная настройка администратора, защищённые сессии и профиль.
- Музыкальный upload pipeline, метаданные, artwork, Range streaming, избранное, очередь и плейлисты.
- Docker Compose для SQLite и PostgreSQL, автоматические миграции и healthcheck.
- Backend, frontend и браузерные smoke-тесты.

### Security

- Проверка production-секрета при старте и изоляция локальных данных от Git/Docker-контекста.
- Обновлены зависимости с опубликованными исправлениями безопасности.
